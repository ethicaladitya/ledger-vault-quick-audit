# LedgerVault

LedgerVault is a private, self-hosted workspace for preparing an Indian income-tax return (ITR) from your bank and credit-card statements. You upload statements, it categorises every transaction, cancels out credit-card bill payments and self-transfers, flags what needs attention, and produces an Excel working paper for your Chartered Accountant.

It is not tax-filing software. Every tax note is a prompt for review, and the treatment stays provisional until your CA confirms it.

## Using it

1. **Create your account.** The first person to open a fresh install becomes the owner. After that, registration is closed unless `ALLOW_REGISTRATION=true`.
2. **Upload & statements.** Name the account (e.g. "HDFC Savings"), choose *Bank account* or *Credit card*, and drop in the statement files for the financial year. Supported: **CSV, XLS, XLSX, or a ZIP of them** (up to 50 MB each). Download these from net banking as Excel/CSV; PDF isn't supported yet. Upload the credit-card statements too, so card bill payments cancel out and the actual purchases are counted.
3. **Overview** shows money in and out for the selected FY, plus *Audit findings*: missing card statements, large unexplained credits, SFT-reportable cash deposits and card spend, interest to declare, and months with no statement.
4. **Transactions → Needs attention** lists UPI/NEFT entries and unrecognised narrations. Pick a category (or click *Confirm*) and add notes for your CA.
5. **Reconciliation** shows matched card-payment and transfer pairs, and what's still open.
6. **Report & export → Download Excel** gives a workbook with *Summary* (by category, with ITR notes), *Flags* and *Transactions* (each with its source file and row).

Re-uploading the same file is ignored. A statement that overlaps an earlier one only adds the new rows. You can delete an uploaded statement from the Upload page.

## Deploy

On a fresh Ubuntu server with DNS pointing at it:

```sh
git clone <this repo> ledgervault && cd ledgervault
SITE_ADDRESS=your.domain ./setup.sh     # installs Docker, generates secrets in .env, starts everything with HTTPS
```

To update an existing server, either run `git pull && ./deploy.sh` on the server, or run this from your own machine:

```sh
./remote-deploy.sh user@server /path/to/ledgervault/on/server ~/path/to/key.pem
```

Database schema upgrades run automatically when the API starts.

### Local development

```sh
cd backend && pip install -r requirements-dev.txt && uvicorn app.main:app --reload    # SQLite by default
cd web && npm install && API_URL=http://localhost:8000 npm run dev                   # http://localhost:3000
```

Alternatively, `cp .env.example .env`, fill in secrets, and run `docker compose up --build`, then open http://localhost.

## Configuration (`.env`)

| Variable | Purpose |
| --- | --- |
| `POSTGRES_*`, `DATABASE_URL` | Database credentials (generated by `setup.sh`) |
| `JWT_SECRET` | Session signing key, at least 32 random characters. The API refuses to start without it. |
| `SITE_ADDRESS` | Your domain, for automatic HTTPS via Caddy. Empty means plain HTTP on port 80. |
| `ALLOW_REGISTRATION` | `false` (default): only the first account can sign up |

## Privacy & security

- Your statements and the database stay on your server. There is no telemetry, analytics or external AI call.
- Each account's data is isolated. Every API route except health and login requires a session and is scoped to the user's workspace.
- Brute-force protection on login, scrypt password hashing, no public API docs, `noindex` headers, and non-root containers.
- Never commit real statements, `.env` or SSH keys. `.gitignore` blocks common statement formats (`*.csv` outside `sample-data/`, `*.xls*`, `*.pdf`, `*.zip`) and `*.pem`.
- Still to do before sharing with others: encrypted backups, encryption at rest, and moving the session token from localStorage to an HttpOnly cookie.


## Adding a bank format

The generic parser in `backend/app/services/ingestion.py` finds the header row and maps common column names (`COLUMNS`). If a bank's export isn't recognised, add its header names there along with a synthetic fixture in `backend/tests/test_parsers.py`.
